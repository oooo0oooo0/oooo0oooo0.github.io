## git-who

[https://github.com/sinclairtarget/git-who](https://github.com/sinclairtarget/git-who)

git-who 是一个「面向文件树的 git blame」，用于按作者统计代码贡献。它关注的不是「某一行代码是谁写的」，而是「某个仓库、某个目录、某个文件主要是谁在维护」。

安装后二进制名为 `git-who`。因为 Git 会把 PATH 中的 `git-xxx` 识别为子命令，所以可以直接用 `git who` 调用，也可以执行 `git-who`。

安装：

``` bash
# macOS / Linux 使用 Homebrew
brew install git-who

# 已安装 Go
go install github.com/sinclairtarget/git-who@latest
```

也可以直接从项目的 releases 页面下载预编译二进制。

使用：`git who [subcommand] [options...] [revisions...] [[--] paths...]`

顶层选项：

``` bash
-color      强制开启 ANSI 颜色输出（覆盖 NO_COLOR 环境变量）
-v          开启调试日志
-version    打印版本并退出
```

子命令：

``` bash
table   按作者输出贡献总量表格（默认子命令）
tree    以文件树形式展示每个路径的主要贡献者
hist    以时间线形式展示每个日期的贡献
```

贡献的默认衡量口径是提交数，也可以用 `-f` 切换为变更文件数、用 `-l` 切换为增删行数。

### git who table

默认子命令，`git who` 等价于 `git who table`，输出按作者汇总的贡献表格。

``` bash
-author value     只统计这些作者的提交，可重复指定
-c                按首次修改（创建时间）排序
-csv              以 csv 格式输出
-e                显示每个作者的邮箱
-f                按变更文件数排序
-l                按新增 + 删除行数排序
-m                按最后修改时间排序
-merges           将 merge 提交计入提交总数
-n int            限制表格行数（0 表示不限制）(default 10)
-nauthor value    排除这些作者的提交，可重复指定
-since string     只统计该日期之后的提交
-until string     只统计该日期之前的提交
```

示例（摘自官方 README，以 CPython 仓库为例）：

``` bash
$ git who
┌─────────────────────────────────────────────────────┐
│Author                            Last Edit   Commits│
├─────────────────────────────────────────────────────┤
│Guido van Rossum                  2 mon. ago   11,213│
│Victor Stinner                    1 week ago    7,193│
│Fred Drake                        13 yr. ago    5,465│
│...3,026 more...                                     │
└─────────────────────────────────────────────────────┘
```

还可以追加路径、分支或任意 commit-ish 来限定统计范围：

``` bash
git who Tools/     # 只看 Tools/ 目录
git who v3.7.1     # 只看该 tag 可达的提交
```

### git who tree

以树形结构展示每个目录 / 文件的主要贡献者，适合快速了解仓库的模块归属。

``` bash
-a                显示不在工作区中的文件（并对所有文件加注）
-author value     只统计这些作者的提交
-c                按首次提交时间对作者排序
-d int            限制树的深度
-e                显示每个作者的邮箱
-f                按涉及文件数对作者排序
-l                按新增 / 修改行数对作者排序
-m                按最后提交时间对作者排序
-merges           将 merge 提交计入提交总数
-nauthor value    排除这些作者的提交
-since string     只统计该日期之后的提交
-until string     只统计该日期之前的提交
```

示例（摘自官方 README）：

``` bash
$ git who tree Parser/
Parser/.........................Guido van Rossum (182)
├── lexer/......................Pablo Galindo Salgado (5)
│   ├── buffer.c................Lysandros Nikolaou (1)
│   └── lexer.c
├── Python.asdl.................Benjamin Peterson (14)
├── parser.c....................Pablo Galindo Salgado (34)
├── string_parser.c.............Victor Stinner (10)
└── token.c.....................Pablo Galindo Salgado (2)
```

未被加注的文件（例如上面的 `lexer.c`），说明对它贡献最多的人与所属目录相同，这是为了减少视觉噪音；用 `-a` 可以强制标注每个文件。

### git who hist

以时间线柱状图展示各时间区间的贡献分布。

``` bash
-author value     只统计这些作者的提交
-e                显示每个作者的邮箱
-f                按涉及文件数对作者排序
-l                按新增 / 修改行数对作者排序
-merges           将 merge 提交计入提交总数
-nauthor value    排除这些作者的提交
-since string     只统计该日期之后的提交
-until string     只统计该日期之前的提交
```

示例（摘自官方 README）：

``` bash
$ git who hist
1990 ┤ #                                     Guido van Rossum (105)
1991 ┤ ##                                    Guido van Rossum (445)
1992 ┤ ###                                   Guido van Rossum (606)
1993 ┤ #-                                    Guido van Rossum (200)
1994 ┤ ###                                   Guido van Rossum (525)
1995 ┤ ####-                                 Guido van Rossum (869)
1996 ┤ ####---                               Guido van Rossum (961)
1997 ┤ #######--                             Guido van Rossum (1,626)
1998 ┤ #####------                           Guido van Rossum (1,205)
1999 ┤ ###-----                              Fred Drake (755)
```

### 常用组合

``` bash
# 列出全部作者，不做行数限制
git who table -n 0

# 带上邮箱，按增删行数排序
git who table -l -e

# 只看某个时间窗口的贡献
git who table --since 2025-01-01 --until 2025-06-30

# 排查某个作者改动了哪些目录
git who tree -d 2 -author someone

# 只看某人的提交时间线
git who hist -author someone
```

### 两个实用细节

- **`.mailmap`**：同一个人如果用过多个名字或邮箱，git-who 会遵循仓库根目录的 `.mailmap`，把贡献归并到同一个作者。
- **`.git-blame-ignore-revs`**：如果仓库根目录存在该文件，git-who 会跳过其中列出的提交（通常用于忽略批量格式化这类提交），文件格式与 `git blame --ignore-revs-file` 相同。

## nano

[https://www.nano-editor.org/](https://www.nano-editor.org/)

nano 是一个小巧友好的终端文本编辑器，界面与操作方式沿袭 Pico，但属于自由软件，并实现了 Pico 所没有的一些能力：同时打开多个文件、按行滚动、撤销 / 重做、语法高亮、显示行号、超长行的软换行等。

安装：

``` bash
brew install nano         # macOS / Linux（Homebrew）
sudo apt install nano     # Debian / Ubuntu
```

使用：`nano [options] [[+行[,列]] 文件]...`，不带文件名则打开一个空缓冲区。

启动时定位光标：

``` bash
nano +12 main.go             # 定位到第 12 行
nano +12,40 main.go          # 定位到第 12 行第 40 列
nano +/TODO main.go          # 定位到第一次出现 TODO 的位置
nano +c/Foo file             # c 表示区分大小写，r 表示按正则解释
nano -                       # 从标准输入读取
```

常用快捷键：

``` bash
Ctrl + G 显示帮助
Ctrl + O 保存（Write Out）
Ctrl + X 退出；直接按 Ctrl + S 再 Ctrl + X 即保存并退出
Ctrl + R 把另一个文件读入当前缓冲区
Ctrl + W 搜索；Ctrl + F 向前搜索，Ctrl + B 向后搜索
Alt  + F / Alt + B 跳到下一个 / 上一个匹配
Ctrl + K 剪切当前行（或已标记的选区）
Ctrl + U 粘贴
Ctrl + 6 标记选区起点，Alt + 6 把选区复制到剪贴缓冲区
Ctrl + J 段落重排（Justify）
Ctrl + T 拼写检查
Ctrl + C 显示光标位置
Ctrl + V / Ctrl + Y 下一页 / 上一页
```

常用命令行选项（短选项与长选项等价）：

``` bash
-h, --help                  显示帮助并退出
-V, --version               显示版本并退出
-v, --view                  只读模式，禁止编辑
-m, --mouse                 开启鼠标支持
-l, --linenumbers           显示行号
-i, --autoindent            新行自动保持与前一行相同的缩进
-c, --constantshow          状态栏常驻显示光标位置
-t, --saveonexit            退出时直接保存已修改的缓冲区，不再提示
-k, --cutfromcursor         剪切改为「光标到行尾」，而不是整行
-Z, --zap                   未修改的退格 / 删除键直接擦除标记区域
-b, --breaklonglines        超过宽度时自动硬换行
-w, --nowrap                不自动硬换行（默认行为，与 -b 相反）
-S, --softwrap              超长行在屏幕上折行显示
-a, --atblanks              软换行时优先在空白处断行
-T number, --tabsize=number              Tab 宽度，默认 8
-r number, --fill=number                 重排与硬换行的目标宽度，0 或负数表示按屏幕宽度
-o directory, --operatingdir=directory   切换并限制只在该目录及其子目录内读写
-Y name, --syntax=name                   指定语法高亮方案
-f file, --rcfile=file                   只读取该配置文件，忽略系统与用户的 nanorc
-R, --restricted            受限模式：只读写命令行上指定的文件
-B, --backup                保存时把旧版本备份为「文件名~」
-P, --positionlog           记住最近编辑过的 200 个文件的光标位置
-x, --nohelp                不显示底部的两行帮助
--modernbindings            使用 ^X 剪切、^C 复制、^V 粘贴等现代键位
```

补充说明：

- 上表中多数选项也可以在运行期间通过 `M-`（Alt）组合键开关，具体见 `Ctrl + G` 帮助里的 Toggles 部分。
- 默认键位与选项可以写在 `~/.nanorc` 或系统级 `nanorc` 中自定义，语法见 `nanorc(5)`。
